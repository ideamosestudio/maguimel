# Auditoría de seguridad, rendimiento y accesibilidad — 2026-09-30

Base: `84327ad` de `ideamosestudio/maguimel`, rama `main`. Cambios preparados mediante PR; no se fusiona ni se modifica la configuración de producción. Pages continúa publicando `main:/docs` con `textilmaguimel.com.ar`.

## Cambios

- Dependencias: React/React DOM/RSC 19.2.8, Vite 8.3.1, Vinext 1.0.0 y complemento RSC compatible; actualización de dependencias transitivas. Override acotado de `satori > fflate` a 0.7.5: corrige la alerta de ZIP sin aceptar el downgrade incompatible propuesto por `npm audit fix --force`. Revisar ese override cuando Satori incorpore la corrección.
- CSP por página: scripts propios y hashes SHA-256 del contenido inline exacto, sin `unsafe-eval` ni `unsafe-inline` para JavaScript. Conexiones limitadas al propio sitio y al endpoint de contacto; mapas limitados a Google; objetos y base URL bloqueados. Los estilos inline se conservan porque forman parte del diseño y del render de React. Política de referrer explícita.
- Contacto: límite de espera de 20 segundos, protección contra envíos concurrentes y confirmación solamente cuando el JSON devuelve `ok: true`. El PHP rechaza arrays, UTF-8 inválido, campos excesivos, tipos de consulta desconocidos y saltos de línea en el email; limita el cuerpo declarado a 16 KB y añade `nosniff`. Se conserva el honeypot y la lista CORS. Los datos no se insertan como HTML ni se almacenan en el navegador.
- Accesibilidad: diálogo nativo con Escape, foco contenido y devolución del foco; contraste de textos secundarios corregido; foco visible; control de pausa del carrusel y respeto de movimiento reducido/punteros táctiles. El contenido de las páginas internas queda visible si JavaScript no funciona.
- Rendimiento: logo de 55.602 a 11.926 bytes; diapositivas secundarias descargadas después de la carga inicial (4 s, antes del primer cambio a los 12 s), y omitidas con movimiento reducido; conserva WebP, fuentes locales con swap y lazy loading de galerías/mapas. CSS de fuentes reducido a Latin/Latin-ext; HTML inicial de referencia de 58.728 bytes a aproximadamente 35 KB. No se cambia la tipografía ni la composición.
- SEO: canonical por ruta con barra final, metadatos y datos estructurados existentes conservados, sitemap actualizado; 404 real y mínima con noindex, sin copiar la portada ni su canonical.
- GitHub: CI con permisos de lectura, acciones fijadas por SHA y checkout sin credenciales persistentes. Ejecuta instalación reproducible, lint, tipos, auditoría, build, controles del artefacto, sintaxis PHP, pruebas de entradas PHP y navegador. Dependabot semanal para npm y Actions. El workflow no despliega ni cambia la fuente de Pages.

## Verificaciones

- `npm audit`: 13 alertas iniciales (10 altas, 2 moderadas, 1 baja), 0 conocidas después de la actualización. Es una consulta puntual al registro, no una garantía permanente.
- Lint, tipos, build y controles de las cuatro rutas: recursos, CSP/hashes, canonical, metadata, idioma, enlaces externos, 404, dominio y exclusión de PHP/credenciales/sourcemaps del artefacto.
- Chrome y axe: inicio, colegio, publicidad y trabajo a 390 y 1366 px. Sin desbordamientos, imágenes rotas, errores de JavaScript/CSP ni infracciones WCAG A/AA detectadas. Galería con teclado y restauración de foco; formulario con éxito/error simulados sin enviar correo real. Las pruebas automáticas no equivalen a una certificación de accesibilidad.
- Búsqueda de firmas de claves privadas y tokens GitHub/AWS/Stripe: 293 blobs de texto del historial alcanzable, sin coincidencias. No es un escaneo exhaustivo de todos los formatos de secretos y no sustituye secret scanning de GitHub.
- Producción al auditar: HTTPS 200; HTTP redirige 301 a HTTPS; Pages `https_enforced=true`; certificado aprobado para raíz y www con vencimiento informado 2026-11-12. A del dominio: las cuatro IP de GitHub Pages; www CNAME a `ideamosestudio.github.io`. Endpoint de contacto responde 405 a HEAD. No se efectuaron envíos reales ni se certificó entrega de email.
- Lighthouse: los primeros intentos presentaron problemas de limpieza/conexión de Chrome en Windows. Las métricas finales, si se completan, se registran por separado. No atribuir las reducciones de bytes a mejoras de Core Web Vitals reales sin medir la publicación.

## Pendientes y límites

1. **cPanel**: desplegar `cpanel/contact.php` en el endpoint externo y comprobar entrega de correo. GitHub Pages no ejecuta ni publica este PHP. La versión del archivo en producción no se ha verificado. Configurar límites de solicitud/rate limiting y registros de fallos en el servidor/proxy: CORS y honeypot no frenan por sí solos a clientes automatizados. Revisar versión soportada de PHP, TLS y configuración de correo en ese hosting.
2. **Propietario de GitHub/DNS**: confirmar y, si falta, completar verificación del dominio en la cuenta/organización `ideamosestudio`. `protected_domain_state` no ofrece confirmación. La cuenta usada tiene WRITE, no admin. Consultas de protección de rama y secret-scanning devolvieron 404: no se puede distinguir ausencia de configuración de falta de acceso. Revisar protección de main, hacer obligatorio CI, secret scanning/push protection, permisos mínimos y 2FA. No se cambiaron permisos ni secretos.
3. **Cabeceras de servidor**: la CSP meta ofrece protección real de carga de recursos, pero no puede aplicar `frame-ancestors`, HSTS ni otras cabeceras HTTP. No se añaden archivos `_headers` o `.htaccess` que Pages ignoraría. Mantener Pages; una futura capa de proxy requeriría un cambio de infraestructura deliberado.
4. **Rendimiento**: permanece JavaScript del framework. Evitar una reescritura de arquitectura dentro de esta auditoría; considerar una extracción de interactividad si una medición posterior muestra que ese peso domina el LCP/INP. Revisar CWV de campo tras publicar y acumular tráfico; Lighthouse es una prueba de laboratorio y no mide INP de usuarios reales.
5. La actualización de Vinext emite avisos de imágenes CSS relativas y partición de módulos. Los recursos se verifican en navegador y en el artefacto; los avisos no impiden compilar.
